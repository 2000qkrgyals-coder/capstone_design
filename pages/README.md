# V5 수정 사항

- 자동 최적화 결과를 `시나리오에 적용`할 때 이미 생성된 Streamlit 슬라이더 키를 직접 수정하던 오류를 제거했습니다.
- 최적화 적용은 버튼 콜백에서 모델 상태만 갱신하고, 포커스 슬라이더 값은 다음 rerun에서 위젯 생성 전에 반영합니다.
- `기준 권고로 복원`, `1~40 전체 개방`, `±5개 조정`, 데이터 편집기 동기화와 동일한 안전한 상태 갱신 패턴을 사용합니다.

# ICN T2 가상 운영 시나리오 & AI 의사결정 지원 시스템

2025년 9월 인천공항 T2 운영 데이터를 재생하여 체크인 카운터 라인, 셀프 체크인 기기, IM1/IM2 출입문 운영안을 바꿨을 때의 대기·혼잡 변화를 비교하는 Streamlit MVP입니다.

## 1. 포함 기능

### ① 운영 현황
- 2025-09-01 ~ 2025-09-30 날짜 선택
- 15분 단위 기준 시각 선택
- 계획 운영 수 / 인원 기준 필요 수 / 기존 시스템 권고 수 비교
- 향후 60~240분 구역별 인원 부하 히트맵
- 병목 후보 및 항공편 수요 표시

### ② 시나리오 설정
- 유인 체크인 라인 A/C/D/E/H/J/K/M/N을 각각 **1~40번 연속 슬롯**으로 취급
- 선택 라인을 슬라이더로 조정
- `1~40 전체 개방`, `기준 권고 복원`, `±5개` 빠른 조작
- 셀프 체크인 B/F/G/L은 별도 기기 자원
- IM1/IM2는 최대 6개 출입문으로 별도 편집
- 항공사별 수요 -30% ~ +50% 충격 적용
- 항공편 좌석 비중을 이용해 관련 구역 수요에 비례 반영

### ③ 결과 비교
- 기준안 vs 변경안 평균 대기시간
- P90 대기시간
- 최대 대기열
- 혼잡 지속 시간
- 피크 필요 인력
- 시간대별 총 대기·부하 인원
- 구역별 대기시간 비교
- 변경안 대기시간 히트맵
- 병목 순위
- Monte Carlo 반복 비교

### ④ 자동 최적화
- 목표 선택
  - 균형 운영
  - 대기시간 최소화
  - 최소 인력 운영
- 추가 투입 가능 인력 제한
- 기존 운영안의 최소 유지 비율 준수
- 각 라인 40개 상한 준수
- IM1/IM2 6개 상한 준수
- 추가 / 감축 / 구역 간 재배치를 반복 탐색
- 결과를 수동 시나리오에 바로 적용 가능

### ⑤ AI 운영 질의
예시:

> 현재 혼잡도가 높은데 추가 인력 4명으로 앞으로 2시간 동안 어떤 조치를 하는 것이 가장 효과적이야?

질문에서 다음 조건을 자동 추출합니다.
- 항공사명
- 수요 변화율(%）
- 추가 직원 수
- 분석 시간 범위
- 최적화 목적

AI가 직접 수치를 계산하지 않고, 먼저 시뮬레이션/최적화 엔진을 실행한 후 구조화된 결과만 설명합니다.

지원 방식:
- 내장 분석: API Key 없이 동작
- OpenAI: 선택적 연동
- Gemini: 선택적 연동

## 4. AI API Key 설정

API를 사용하지 않아도 `내장 분석`은 작동합니다.

외부 AI를 연결하려면:

1. `.streamlit/secrets.toml.example`을 복사
2. 파일명을 `.streamlit/secrets.toml`로 변경
3. 필요한 키 입력

```toml
OPENAI_API_KEY = "..."
GEMINI_API_KEY = "..."
```

키 파일은 `.gitignore`에 포함되어 GitHub에 올라가지 않습니다.

## 5. 모델링 원칙

### 기준 운영안
기존 운영 최적화 앱의 다음 로직을 재현합니다.
- 계획 운영 수와 실시간 필요 수 차이가 2 이상이면 추가
- 차이가 -2 이하이면 감축 검토
- 감축 시 구역 유형별 최소 유지 비율 적용

최소 유지 비율:
- A 프리미엄: 70%
- B/F/G/L 셀프: 50%
- 일반 체크인: 60%
- IM1/IM2: 50%

### 원본 데이터에서 확인한 필요 수 규칙
- 일반 체크인: `ceil(실시간인원수 / 5)`
- 셀프 체크인: `ceil(실시간인원수 / 6)`
- IM1/IM2: `ceil(인원 / 30)`, 수요가 있으면 최소 3개, 최대 6개
- A 프리미엄 계획 운영 수: 계획수요 약 8명당 1개

### 대기시간
실제 승객별 서비스 시작/종료 로그가 없기 때문에 앱의 대기시간은 직접 관측값이 아닙니다.

1. 1분 단위 `실시간인원수`와 기준 운영 수로 분당 유입량을 역산
2. 기존 자원 산정 규칙과 목표 대기시간을 일관되게 연결한 처리율 사용
3. 기준 운영과 변경 운영에 동일 수요를 투입
4. 결과 차이를 비교

따라서 절대 대기시간보다 **기준안 대비 개선/악화 정도**를 중심으로 해석해야 합니다.

### 항공사 수요 시나리오
좌석 수를 그대로 승객 수로 더하지 않습니다.

- 출발 180~60분 전을 체크인 영향 구간으로 설정
- 출발 약 120분 전에 가장 높은 가중치
- 항공사별 좌석 가중치로 해당 구역에서의 항공사 점유율 계산
- 기존 9월 유입량에 점유율만큼 수요 변화율 적용

이 방식은 원본 운영 데이터의 스케일을 유지하면서 항공사별 증가/감소 효과를 반영하기 위한 것입니다.

### 체크인 → IM 병목 전이
변경안에서 체크인 처리량이 기준보다 증가하면, 설정한 이동시간(기본 8분) 뒤 IM1/IM2 유입량이 증가합니다.
IM1/IM2 배분 비율은 당시 실제 IM 구역 인원 비중을 평활화하여 사용합니다.

## 6. 중요한 제한사항

현재 버전은 **9월 과거 데이터 재현형 의사결정 지원 프로토타입**입니다.

실제 공항 실시간 운영에 적용하려면 추가로 필요합니다.
- S-WARD 신규 데이터 자동 수신
- 승객별 실제 체크인/보안검색 서비스 완료 로그
- 각 카운터 라인의 실제 물리 배치표
- 항공사별 독점/공용 카운터 운영 규칙
- 직원 교대시간, 휴게시간, 직무 자격 등 근무 제약
- IM1/IM2 실제 처리량 검증

## V6 변경사항 — 전 시간대 비악화 최적화

- 자동 최적화의 기본 조건을 `전 시간대 비악화 보장`으로 강화했습니다.
- 현재 집계 데이터로 관측 가능한 다음 세 지표가 매 1분마다 기준 운영보다 높아지지 않는 후보만 엄격 최적화 후보로 인정합니다.
  1. 전체 추정 대기부하(전체 구역 queue 합계)
  2. 대기열 가중 평균 대기시간
  3. 해당 시각 최악 구역의 추정 대기시간
- 시작 시점은 동일한 초기 상태를 공유하므로 `무조건 더 작음(<)`이 아니라 `증가하지 않음(<=)`을 사용하고, 적어도 한 시간대에서 개선이 있어야 실질 개선으로 표시합니다.
- 결과 비교 그래프에 개선/악화 구간 음영, 총 대기부하 교차 시점, 개선 시간 비율, 악화 시간, 최대 순간 악화, 누적 대기부하 절감(인·분)을 추가했습니다.
- 엄격 조건을 만족하는 개선안이 없으면 기준 운영안을 유지하고, 억지로 평균만 좋은 운영안을 `최적화안`으로 표시하지 않습니다.
- 항공사 수요 변화가 적용된 경우 자동 최적화는 동일한 수요 조건의 현재 권고 운영안과 비교합니다.
